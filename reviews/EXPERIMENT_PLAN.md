**配套文件**：`FINAL_META_REVIEW.md`（问题编号 S1–S3、A1–A8、B1–B16、#1–#38 都出自那里）
**版本说明**：已整合 2 份 Haiku 评审（第 4 个模型家族）。新增或修改的内容有：E0.11–E0.16、E1-h、E2-c、E8 的扩展；另外明确说明了**不采纳** Haiku 提出的"计算匹配基线"（理由见 E1 后的说明）。P0 的算力估算基本不变，新增条目大多是零训练成本的分析。
**核心目标**：把论文主张与证据之间的缺口补上，满足 TMLR 的第一条标准，同时尽量不让新实验推翻论文的主线。每个实验都写明了结果好或坏时论文应该怎么改。

## 0. 记号与算力单位

- **1C** = 原文一整套全数据运行的算力：3 个骨干 × 7 个数据集 × 4 个 horizon × 5 个种子 = **420 次训练**。原文主实验约 11C（全数据 + 5 个单元 × high/low 两端），再加上 §7。
- **"减配"**指为省算力缩小网格，比如把种子从 5 降到 3，或减少骨干、数据集、horizon。减配只用于次要实验，**主表实验（E1、E2）建议保持全网格**，因为它们要直接放进表 1 和表 2，口径必须和原文一致。
- 不同实验的单次运行时间差别很大，ECL 和 solar 最慢，ETT 最快。所以下面的 C 值是按**运行次数**粗估的，实际 GPU 小时要按数据集加权。
- **预先登记（建议）**：在跑 E1–E5 之前，把主要假设、主要指标（MAE 和 MSE **同时作为主指标**）和主要检验写进一份内部文档，事后在附录中声明。这样能直接回应"多重比较"和"指标是事后挑的"这类质疑，TMLR 审稿人很认可这种做法。

### E1. 鲁棒损失和在线截断对照（**全文最关键的实验**）

**目的**：回应 S1，把"单元或得分的特异性收益"与"一般的鲁棒化收益"区分开。

**设置**：3 个骨干 × 7 个数据集 × 4 个 horizon；主表用 5 个种子，算力不足时用 3 个。其他条件与原文完全相同（TSLib 配方，按验证损失选 epoch）。验证损失统一用**未屏蔽的 MSE**，以便和原文可比；同时报告用各自训练损失选 epoch 的敏感性结果。

| 配置 | 说明 | 目的 |
|---|---|---|
| E1-a L1 | 全数据，L1 损失 | 检验"MAE 收益是不是只来自损失与指标不匹配" |
| E1-b Huber | 全数据，Huber/SmoothL1；δ 先在 ETTh1、weather 两个数据集的验证集上从 {0.25, 0.5, 1, 2}（标准化尺度）中选，然后固定（选 δ 约 +0.3C） | 软截断基线 |
| E1-c online-trim（occurrence） | 全数据，每个 mini-batch 内按当前残差把最高 10% 的 occurrence 权重置 0，不需要打分运行 | loss truncation / LTS 的直接对应，检验"固定的早期掩码"有没有额外价值 |
| E1-d online-trim（window） | 每个 mini-batch 内丢弃损失最高的 10% 窗口 | 与已有窗口级时间序列方法（例如 Liu et al. 2025 的早期丢弃高损失样本）在思路上对应 |
| E1-e mask(occ)+L1 | occurrence high-end 掩码 + L1 损失 | 检验两者是互补还是重叠 |
| E1-f mask(chan.row)+L1 | channel row high-end 掩码 + L1 损失 | 同上，针对推荐单元 |
| （可选）E1-g 软加权 | 按早期残差分位数连续降权，例如 w = 1/(1+r/r̄) | 检验硬掩码是否必要（B10） |
| （可选）E1-h 先丢弃后恢复 | 前若干 epoch 屏蔽 high-end occurrence，之后恢复全部监督（对应 Liu et al. 2025） | 与论文 §2 引用的最接近已有工作直接比较（B14）；如果恢复后收益消失，就说明收益依赖于"一直不学这些项" |

> **不建议做的"计算匹配基线"**（两份 Haiku 评审都提出过）：给全数据基线多训 10% 的 epoch。理由是：打分运行的权重会被丢弃，掩码模型的训练步数与基线相同，不存在"多出的训练步数"；而且所有运行都按验证集选最佳 epoch，多给 epoch 对基线几乎没有影响。这个问题应该用 E0.15 的总成本披露来回应，而不是用一组新实验。

**报告指标**：MAE、MSE、median |e|、q90、CVaR@90%（**必须同时报告 MSE 和 CVaR，不能只看 MAE**），并在 L1 损失下重画图 2(a) 的分位数剖面。

**主要检验**（预先登记）：
- H1："mask(high) vs online-trim(occ)"的 MAE 和 MSE；
- H2："mask(high) vs L1"的 MSE（预期 L1 会损害 MSE）；
- H3："mask+L1 vs L1"的 MAE；
- H4：在 L1 下，五个单元的排序是否保持。只做 E1-e 和 E1-f 两个单元时，可以先检验 window 与 occurrence 的差距在 L1 下是否依然存在；全面检验需要在 L1 下跑全部单元，约 +3C，放 P1。

**决策树**（与 `FINAL_META_REVIEW.md` §6.2 一致）：

| 结果 | 论文怎么写 |
|---|---|
| A：掩码 MAE ≈ 或 > L1/Huber，且掩码 MSE 改善而 L1 的 MSE 变差 | **最强卖点**："targeted masking 拿到鲁棒损失的 MAE 收益，又不牺牲 MSE"。写进摘要的第一个发现 |
| B：L1 的 MAE 与掩码持平，掩码 MSE、CVaR 更好 | 定位为"保留 MSE 目标的鲁棒训练替代方案" |
| C：mask+L1 明显优于 L1 | "单元重要"的主张不依赖损失函数，核心叙事保留 |
| D：固定早期掩码优于 online-trim | 新结论："一次性早期决定优于逐批截断"（原因可能是在线截断在训练早期误删了难但可学的项），写进摘要 |
| E：L1/Huber 在 MAE 和 MSE 上都 ≥ 掩码，且 mask+L1 ≈ L1 | 重新定位为"滑动窗口中截断粒度的系统研究"，删去实践推荐，保留机制贡献（窗口自相关 → 定位精度；element 与 occurrence → 上下文依赖） |

**风险提示**：E1 有可能削弱论文。但**不做 E1 的风险更大**，因为 3 个家族的审稿人都把它列为第一条，真实审稿人几乎一定会要求。主动给出结果，哪怕是情况 E，也比在 rebuttal 中被动补实验好得多。

### E2. 每个单元的同预算随机屏蔽

**目的**：回应 S2。low end 在 MSE 下几乎必然无效，不能证明"收益来自屏蔽了哪些项，而不是屏蔽本身"。

**设置**：五个单元，每个都在 r=10% 下均匀随机选择成员。**每个种子用不同的随机掩码**，让方差把掩码的随机性也包含进去。全网格，5 个种子，或减配为 3 个。

**另做一个"结构匹配随机"**（推广 §7.1 的做法）：在 DLinear 和 TimeMixer 上也跑 element 单元的"段长和时段都匹配"的随机掩码（约 0.3C），把原来只有 iTransformer 的对照推广到三个骨干。

**产出**：表 1 和表 2 每个单元下增加一行 "random"；Friedman 检验把 random 也纳入；图 1 增加随机柱。

**附加 E2-c：剂量-反应（Haiku·high 的建议，约 +0.6C）**：在 occurrence 和 channel row 两个单元上，分别屏蔽残差在 {0–10, 25–35, 45–55, 65–75, 90–100} 分位区间的成员（每段都是 10% 预算）。骨干用 DLinear 和 iTransformer，7 个数据集，horizon 取 {96, 336}，3 个种子。
- 如果收益随残差分位**单调**增加，说明"残差越高越该屏蔽"，就能把 high end 与 low end 的二元对比升级为一条剂量-反应曲线。这对 TMLR 读者非常有说服力，也直接加强 S2。
- 如果收益只在最高段出现，说明机制更像"离群点剔除"，与 S1 的鲁棒化解释一致，应据此调整论文表述。

**结果解读**：
- random 接近 0、high end 明显为负：**"选对了项"得到直接证据**，S2 的一半就解决了。
- random 在某些单元（比如 window）也有约 −1% 的收益：要把这部分写成"非特异性正则化"，并且只把**相对 random 的差值**作为"选择"的贡献。主表可以增加一列"相对 random 的增益"。

## 3. P1：强烈建议（显著提高录取把握）

### E3. 预算扫描

- **设置（减配）**：
  - r ∈ {2, 5, 20, 40}%（10% 已有）；
  - 单元取 {window, channel row, occurrence, element}（time column 可省，因为它与 channel row 结果接近）；
  - 端取 {high, random}，外加 window 和 occurrence 在 r=40% 时的 low end（用来检验"low end 无效"在高比例下是否翻转）；
  - 骨干取 {DLinear, iTransformer}；
  - 数据集取 {ETTh1, ETTh2, ETTm2, weather, solar}；ECL 太贵，可以只跑 r=20%；
  - horizon 取 {96, 336}，3 个种子。
- **产出**：每个单元的 MAE、MSE、CVaR 随 r 变化的曲线（主文一张图）；最优 r；单元排序是否随 r 变化。
- **解读**：
  - 排序稳定：证明"窗口收益最小"不依赖预算；
  - 出现拐点（比如 element 在 40% 时因整段目标缺失而迅速恶化）：写成"预算的推荐范围"，这对实践者是加分项。

### E4. 按残差质量匹配的单元比较

- **步骤**：
  1. 用 E0.4 的残差在不训练的情况下算出：每个单元要达到 occurrence@10% 移除的残差质量，需要多大的 r_u（例如 window 可能需要 25%）；
  2. 只训练这几个匹配后的配置（减配网格同 E3，约 0.6C）；
  3. 结合 E3 的曲线插值。
- **解读**：
  - 匹配质量后各单元**差别消失**：主张改为"定位精度"；
  - **仍有差别**：说明单元结构本身重要，这是更强的结论。
  - 两种结果都能写成正面贡献。

### E5. 时间序列结构对照

| 子项 | 做法 | 检验什么 |
|---|---|---|
| E5.1 lead-time 设预算上限的 occurrence 掩码 | 在每个 lead time 位置内部各取 top-10% | occurrence 的收益是不是来自隐式降低远步长的权重 |
| E5.2 通道设预算上限的掩码 | channel row 和 element 在每个通道内各取 top-10% | ECL 上 MSE 上升是不是因为掩码集中在少数通道 |
| E5.3 无得分的远步长降权 | 每个窗口都屏蔽最后 ⌈0.1T⌉ 个步长（恰好 10% 的项） | 对应 Hounie et al. (2024) 的 loss shaping；如果它能复现 occurrence 的大部分收益，叙事就要改 |
| E5.4 时间位置对照 | 屏蔽训练段最早的 10% 目标，以及最晚的 10% 目标 | "去掉某个 regime"的机制，以及漂移风险 |

- **设置**：3 个骨干 × 7 个数据集 × 4 个 horizon × 3 个种子，4 个配置，约 2.4C；如果 E0.5 显示 lead time 和通道分布都均匀，可以只做 E5.3 和 E5.4（约 1.2C）。
- **解读**：
  - 设上限的掩码 ≈ 原掩码，且 E5.3 远弱于原掩码：直接排除 lead time 混杂，A3 的核心质疑就解决了；
  - 反之，要如实报告，并把"lead time 选择"写成机制之一。这同样有价值，因为它把本文与 loss shaping 联系了起来。

### E6. 合成或注入异常的受控实验（机理价值高、成本低）

- **底座**：①合成序列（多周期正弦 + AR(1) 噪声，D=7，长度与 ETTm1 相当）；②真实的 ETTm1。
- **注入 4 类异常**（各占 1–2% 的 element，位置已知），每类对应一个单元结构：
  - 点尖峰：occurrence 或 element 结构；
  - 单通道片段异常：channel row 结构；
  - 跨通道同一时刻的事件：time column 结构；
  - 水平漂移或 regime：时间段结构。
- **再注入"罕见但可学"的模式**：一个在训练集和测试集中都会以低频重复出现的特殊周期 motif。
- **测量**：
  - 每个单元掩码对异常的 precision 和 recall；
  - 在干净测试集上的收益；
  - 在含 motif 的测试段上的收益。后者用来检验掩码会不会误删"难但可学"的目标，这正对应尾部风险。
- **设置**：DLinear + iTransformer，horizon 取 {96, 336}，3 个种子，配置为 {full, 5 个单元 high, random, L1}，约 0.5C（ETTm1 规模较小）。
- **解读**：
  - "与异常结构匹配的单元胜出"：直接给出"何时哪个单元最好"的机制性答案，这是 TMLR 读者最感兴趣的内容；
  - 掩码对 motif 的误删率可以写成方法的局限性；
  - 同时，这个实验还能回应 A4：从"同义反复的相关性"升级为"在已知真相上验证得分选中了什么"。

### E7. §7.3 补全（让"省算力"的主张有证据，或者干脆降级）

- **设置**：
  - 删窗率取 {10, 30, 50, 70, 90}%；
  - 规则取 {等间距, 随机, 三条按得分的规则}，三条规则要**在论文中定义**；
  - 是否叠加 element 掩码取 {有, 无}（"无"是 Fable·high 指出缺失的对照）；
  - 骨干取 iTransformer（可能已有）+ DLinear；6 个数据集，4 个 horizon，3 个种子。
- **报告**：
  - MSE 和 MAE 曲线；
  - 等间距 vs 随机的 TOST；
  - **wall-clock 和总 FLOPs，包括打分成本**；
  - 与 InfoBatch 和随机重采样（Okanovic et al. 2024）比较，二者都可以在窗口级直接实现。
- **解读**：
  - 结果稳定：§7.3 成为完整的"实用省算力"小节，回应"不省算力"的批评，并调和标题的张力（"监督用 mask，算力靠等间距删窗"）；
  - 结果不稳定：把 §7.3 降级到附录，作为探索性结果。

## 4. P2：建议（进一步消除审稿人的疑虑）

### E8. 打分时刻扫描，以及收敛点上的 §7.1 分解
- 打分时刻取 {epoch 0（未训练）, 10%, 30%, 100%/最佳 epoch}；单元取 {element, channel row}；骨干取 {iTransformer, DLinear}；6 个数据集，horizon 取 {96, 336}，3 个种子（约 0.7C）。
- §7.1 的 5 折分解**在收敛点**重做，并补上 solar 或说明排除理由（约 0.3C）。
- **扩展到 DLinear（收益最大的骨干）和 occurrence 单元（MAE 最好的单元）**，不要只在 iTransformer×element 上做（Haiku·high、Sonnet·high 都提出过，约 +0.4C）。
- 报告：10% 时刻与收敛时刻得分的 Spearman，以及与 untrained 残差的 Spearman。
- **解读**：
  - 收敛点 Spearman 仍然很高：可以恢复较强的表述；
  - 明显下降：把表述限定为"早期训练意义上的未解释"，并补充 RHO-Loss 式的 "training − holdout loss" 得分作为表 3 的新行。

### E9. Selective Learning 官方设置
- 用官方代码、官方默认超参，不做比例校准，单元也保持原样；骨干取 iTransformer + DLinear，6 个数据集。报告实际屏蔽比例，并与 Fu et al. (2025) 报告的数值对照（约 0.5C）。
- 摘要中对 SL 的表述根据结果来定。

### E10. 修复对照的 2×2 分解
- 目标取 {保留, 屏蔽} × 输入取 {原值, 插值}，用 iTransformer，6 个数据集，3 个种子（约 0.3C）。
- 如果"只修复目标"仍然不如屏蔽，就可以保留 "masking beats repairing"；否则改为 "masking beats editing the series"。

### E11. 平凡得分基线
- 得分取 |y − 通道滚动中位数|、季节朴素残差、|Δy|、局部方差，都放在 element 和 channel row 单元上；骨干取 iTransformer + DLinear，6 个数据集，3 个种子（约 0.6C）。
- 与本文得分的 Spearman 相关可以先算，**不需要训练**。
- **解读**：
  - 平凡得分明显更差：说明"模型残差"确实提供了信息，这是对表 3 的加强；
  - 平凡得分与本文得分相当：主动写成"简单的离群统计就够用"，实用价值反而更高。

### E12. 掩码稳定性
- 用 3 个不同的打分种子各生成一次掩码，报告 Jaccard 重叠，以及下游 MAE 和 MSE 的方差。用 DLinear + iTransformer，4 个数据集（约 0.3C）。

### E13. 泛化
- **PatchTST（P2）**：一种通道独立的 patch Transformer。在 7 个数据集上跑核心配置 {full, window, channel row, occurrence, element high, random, L1}，3 个种子（约 1.2C）。
- **L=336（P2）**：DLinear + iTransformer，4 个数据集（约 0.5C）。L 改变后，重叠结构和 c(t,d) 的边界都会变。
- **Traffic（P3）**：862 个通道，检验"ECL 上细单元让 MSE 变差"是否是高维数据的共性。计算成本最高，可以只用 DLinear 跑核心配置。

### E14. 通道相关的诊断
- 得分按通道残差方差标准化后再选，用 ECL 和 weather。
- ECL 通道子采样 D ∈ {7, 21, 64, 321}，检验细单元的 MSE 恶化是否随 D 增大（约 0.5C）。
